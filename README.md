# ระบบสารสนเทศการรับจัดการแข่งขันกีฬา

การวิเคราะห์และออกแบบระบบสารสนเทศสำหรับธุรกิจรับจัดการแข่งขันกีฬาแบบครบวงจร
ตั้งแต่รับความต้องการจากลูกค้า จองสถานที่ ประสานงาน Partner จนถึงส่งมอบผลการแข่งขัน

**รายวิชา** การวิเคราะห์และออกแบบระบบ · ปีการศึกษา 2568
**อาจารย์ที่ปรึกษา** อ.ดร.ศศิน เทียนดี
**ประเภท** โปรเจกต์กลุ่ม 3 คน · มหาวิทยาลัยเกษตรศาสตร์ วิทยาเขตกำแพงแสน

---

## ภาพรวมระบบ

ระบบรองรับผู้ใช้งานหลายบทบาท ได้แก่ ลูกค้าผู้จัดการแข่งขัน พนักงานคีย์ข้อมูล
พนักงานคลังอุปกรณ์ ผู้จัดงาน และ Partner ภายนอกสามกลุ่ม (Partner อุปกรณ์,
Partner สถานที่, Partner อำนวยการ)

## ฟีเจอร์หลัก

1. จัดการข้อมูลพื้นฐาน
2. รับ requirement จากผู้ใช้งาน
3. แสดงสถานะสถานที่
4. จองสถานที่
5. คำนวณค่าบริการจาก requirement
6. เก็บหลักฐานการชำระเงิน
7. เบิกยืมอุปกรณ์กลาง
8. แจ้งรายละเอียดงานไปยังส่วนต่าง ๆ ที่รับผิดชอบ
9. บันทึกประวัติการใช้งานของผู้ใช้
10. รับ feedback จากผู้ใช้

## ขอบเขตงานที่ทำ

### 1. ศึกษาระบบใกล้เคียง

วิเคราะห์เปรียบเทียบระบบสารสนเทศ 5 ประเภทที่มีลักษณะงานใกล้เคียงกัน
ได้แก่ ระบบโต๊ะจีน ระบบจัดอีเว้นท์ ระบบรับจัดงานแต่ง ระบบจัดแข่ง Esport
และระบบรับเหมาก่อสร้าง แล้วคัดเลือกฟีเจอร์ที่เหมาะสมมาปรับใช้กับระบบของเรา
พร้อมระบุเหตุผลประกอบการตัดสินใจแต่ละข้อ

### 2. วิเคราะห์กระบวนการทำงาน

แตกกลไกการทำงานเป็น 28 ขั้นตอนย่อย แล้วจัดกลุ่มเป็น 15 กระบวนการหลัก
เพื่อใช้เป็นฐานในการเขียนแผนภาพกระแสข้อมูล

### 3. แผนภาพกระแสข้อมูล (Data Flow Diagram)

เขียน Context Diagram แสดงขอบเขตระบบและ External Entity ทั้งหมด
จากนั้นแตกเป็น DFD ระดับย่อยครบทั้ง 15 กระบวนการ
พร้อมระบุ External Entity และ Data Store ของแต่ละกระบวนการ

### 4. พจนานุกรมข้อมูล (Data Dictionary)

จัดทำพจนานุกรมข้อมูลสองชุด

- **กระแสข้อมูล (Data Flow)** — รหัสข้อมูล ชื่อข้อมูล คำอธิบาย แหล่งกำเนิด และปลายทาง
- **แหล่งจัดเก็บข้อมูล (Data Store)** — โครงสร้างและรายละเอียดของทุกแฟ้มข้อมูล

### 5. คำอธิบายกระบวนการ (Process Description)

เขียนคำอธิบายเชิงแนวคิดของทุกกระบวนการ ระบุเงื่อนไขและลำดับการทำงาน

### 6. ออกแบบระบบฐานข้อมูล

- วิเคราะห์หา Entity ได้ 20 รายการ แล้วยุบรวมเหลือ **18 แฟ้มข้อมูล**
  (ยุบแฟ้มกรรมการ ช่างภาพ และแพทย์สนาม เข้าเป็นแฟ้มบุคลากร Partner อำนวยการ)
- กำหนด Key Attributes ของทุกแฟ้ม
- วิเคราะห์ความสัมพันธ์ระหว่าง Entity ครบทุกคู่ พร้อมระบุ Cardinality
  (1:1, 1:M, M:M) และเหตุผลประกอบ

### 7. ออกแบบส่วนติดต่อผู้ใช้ (UI)

ออกแบบหน้าจอแยกตามบทบาทผู้ใช้ พร้อมคำอธิบายการทำงานของแต่ละหน้าและแต่ละปุ่ม
ครอบคลุมหน้าจัดการบุคลากร หน้าคลังอุปกรณ์ หน้าคำร้องขอใช้อุปกรณ์
และหน้าคืนอุปกรณ์ ทั้งฝั่งพนักงานภายในและฝั่ง Partner
